# 2D DEM Simulation

## Описание

Это проект для моделирования поведения ансамбля сферических частиц (в 2D — дисков) в замкнутом объёме
(вращающийся барабан). Программа реализует метод дискретных элементов (DEM) с учётом упруго-демпфированных контактов, трения и момента сопротивления качению.

## Особенности

- Моделирование взаимодействия частиц по контактной модели
- Учёт нормальной и касательной силы трения (статического и динамического)
- Момент сопротивления качению
- Веб-интерфейс на Flask: параметры симуляции, превью геометрии, визуализация траекторий частиц и приводного момента
- Ускорение горячего цикла через Numba JIT (силы частица-частица + интегратор)

## Требования

- Python 3.10+ (используется `X | None` в аннотациях без `from __future__`)
- numpy>=1.21.0
- matplotlib>=3.3.0
- Flask
- numba
- PyQt5>=5.15.0 (только для устаревшего GUI в `gui/`)

## Установка

1. Создайте виртуальное окружение:

    ```bash
    python -m venv venv
    ```

2. Активируйте виртуальное окружение:

    - Windows: `venv\Scripts\activate`
    - Linux/Mac: `source venv/bin/activate`

3. Установите зависимости:

    ```bash
    pip install -r requirements.txt
    ```

## Запуск

Запустите основной скрипт:

```bash
python main.py
```

Откройте веб-интерфейс: http://localhost:5000

## Использование

Два режима работы:

1. Вкладка «DEM симуляция»: введите параметры в форме слева, нажмите «Старт» для запуска симуляции (расчёт идёт в фоновом потоке). Результаты отображаются ниже — графики траекторий частиц, график приводного момента и числовые значения (средний/пиковый момент, мощность). Кнопка «Стоп» прерывает расчёт. В режиме реального времени окно предпросмотра геометрии заменяется живым кадром симуляции (барабан, повёрнутые лифтеры, текущие позиции частиц + HUD с шагом/прогрессом/временем). Переключатель «Вычислитель» в форме позволяет выбрать backend: **CPU (Numba JIT)** — по умолчанию, **CPU (чистый Python)** для отладки, **GPU (CuPy)** с автофолбэком на Numba, если CuPy/CUDA установлены (`pip install cupy-cuda12x`, см. ответ `/start`: `gpu_available` сообщает, активен ли реально GPU-путь).

2. Вкладка «Аналитика траекторий»: аналитический расчёт траекторий мелющих тел по модели Moly-Cop (входные параметры — в единицах таблицы `instruct/Media Charge_Trajectories.xls`: футы, дюймы, градусы). После нажатия «Рассчитать» выводится таблица ~50 производных показателей (геометрия, скорости, точки отрыва/удара, скорость/энергия удара, масса/мощность заряда) и график траектории полёта, а также сравнение с эталонными значениями из таблицы Moly-Cop.

## Структура проекта

- `main.py` - точка входа: запускает Flask-приложение из `web/`
- `web/` - веб-интерфейс: `app.py` (эндпоинты `/start`, `/stop`, `/status`, `/partial_results`, `/results`), `live_buffer.py` (потокобезопасный буфер промежуточных результатов), `templates/`, `static/`
- `dem/` - основная логика моделирования
  - `particle.py` - класс частицы
  - `contact_model.py` - модель контакта
  - `geometry.py` - границы (стенки, барабан, лифтеры)
  - `integrator.py` - интегратор Верле
  - `simulation.py` - основной класс симуляции
  - `force_calculation.py` - расчёт сил (CPU/Numba/GPU авто-выбор для пар)
  - `analytical.py` - аналитический расчёт траекторий (Moly-Cop Media Charge Trajectories)
  - `jit_kernels/` - Numba-ядра для горячего цикла
  - `gpu_backend.py` - CuPy-ядра для горячего цикла (опционально)
- `gui/` - устаревший PyQt5-интерфейс (не используется `main.py`)
- `visualization/` - визуализация результатов
- `utils/` - вспомогательные функции и конфигурации (`config.py` — `SimulationConfig`)
- `bench/` - профилирование горячего цикла: `python -m bench.profile_sim`
- `tests/` - unittest: `python -m unittest discover -s tests`
